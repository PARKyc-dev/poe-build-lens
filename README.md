> PoE Lens는 AI가 복잡한 도메인 지식을 어디까지 신뢰성 있게 다룰 수 있는지 경험하고 검증하기 위한 프로젝트입니다.
>
> Path of Exile 1(PoE 1)의 빌드와 메커니즘을 주제로, Path of Building(PoB) 내보내기 데이터를 분석하고 검토된 게임 메커니즘을 설명합니다.

## 이 프로젝트에서 확인하려는 것

```text
복잡한 입력 ──▶ 구조화된 분석 ──▶ 검증 가능한 설명
```

이 프로젝트는 단순히 AI에게 답변을 생성하게 하는 데서 그치지 않고, 다음 질문에 답하는 것을 목표로 합니다.

- AI는 서로 얽힌 규칙과 예외가 많은 정보를 어느 정도 복잡도까지 다룰 수 있는가?
- AI가 설명한 내용을 신뢰할 수 있게 만들려면 어떤 입력, 구조화, 검증 과정이 필요한가?
- 불확실한 정보와 검증된 정보를 어떻게 구분해 사용자에게 전달해야 하는가?

## 왜 Path of Exile 1인가

PoE 1의 빌드는 스킬 하나만으로 결정되지 않습니다. 스킬 젬과 보조 젬, 장비 옵션, 패시브 트리, 방어 계층, 자원 유지, 상태 이상 등 다양한 요소가 서로 영향을 주고받습니다. 따라서 AI가 복잡한 규칙을 해석하고 설명하는 능력을 시험하기에 적합한 주제입니다.

이 주제를 선택한 또 다른 이유는 작성자가 PoE 1을 좋아하고 기본적인 메커니즘을 이해하고 있어, AI의 설명을 직접 검증할 수 있기 때문입니다. 이는 그럴듯하지만 잘못된 설명을 걸러내고, 더 나은 분석 방식을 찾는 데 도움이 됩니다.

| PoE 1의 요소 | 분석에서 확인할 점 |
| --- | --- |
| 스킬 젬 · 보조 젬 | 피해 유형과 보조 효과의 상호작용 |
| 장비 · 옵션 | 빌드에 적용되는 조건부 수정자 |
| 패시브 트리 | 선택한 노드 사이의 연결과 우선순위 |
| 방어 · 자원 유지 | 생존성과 지속 운용을 위한 계층 구조 |

## 현재 기능

- 압축 PoB 코드, `pobb.in` 링크, 원본 XML 입력 지원
- 브라우저 `Web Worker`에서 원본 Path of Building `HeadlessWrapper.lua` 실행
- 고정된 PoB 원본 버전 `v2.67.2`와 Lua/WebAssembly 런타임 사용
- 현재 선택된 패시브 트리·스킬 세트·장비 세트, 활성 스킬, 계산 요약 추출
- 총 DPS, 생명력, 에너지 보호막, 유효 생명력 표시
- 활성 장비의 슬롯, 이름, 베이스, 희귀도, 옵션 표시
- Fireball·Arc의 확인된 규칙을 바탕으로 핵심 메커니즘, 주의점, 강화 우선순위 표시
- Spring Boot API에서 PoB XML·압축 코드 파싱 및 로컬 메커니즘 카탈로그 조회 제공

현재 로컬 카탈로그는 PoE 1 버전 `3.27`을 대상으로 하며, Fireball과 Arc의 초기 데이터만 포함합니다.

## 프로젝트 구조

```text
poe-lens/
├── web/       # React 화면, 브라우저 PoB Worker, PoB 자산 패커
├── api/       # Spring Boot 분석 API와 로컬 메커니즘 카탈로그
├── worker/    # 향후 확장을 위한 빈 예약 영역
├── docs/      # PoB 분석 방향과 프로젝트 맥락
└── memory/    # 작업 상태와 장기 결정 기록
```

`web`은 브라우저에서 PoB를 실행하고 계산 결과와 인사이트를 표시합니다. `api`는 PoB 입력 파싱과 검토된 로컬 메커니즘 카탈로그를 제공하는 독립 서비스입니다. 브라우저 PoB 엔진의 원본 버전 고정과 자산 생성 입력은 `web/pob/`에서 관리합니다.

## 설계 원칙

### 검증된 정보와 미확인 정보를 분리합니다

게임 메커니즘은 패치 버전, 조건, 예외에 크게 영향을 받습니다. 그래서 이 프로젝트는 카탈로그에 검토된 근거가 있는 항목만 설명하고, 정보가 없는 항목은 미확인으로 표시합니다.

### 재현 가능한 분석을 우선합니다

PoB 원본 버전과 자산을 고정하고, 브라우저에서 같은 입력을 같은 PoB 엔진으로 분석합니다. 같은 입력에 대해 일관된 결과를 얻고, 어떤 근거를 바탕으로 설명했는지 추적하기 위해서입니다.

### 복잡도를 단계적으로 확장합니다

처음부터 모든 PoE 메커니즘을 해석하려 하지 않습니다. 스킬, 아이템, 방어, 자원 유지처럼 분석 단위를 확장하며, 각 단계에서 AI가 정확하게 다룰 수 있는 범위와 필요한 검증 방식을 확인합니다.

## 한계와 다음 단계

- 패시브 트리의 선택 노드와 연결 정보는 추출하지만, 화면 렌더링은 진행 중입니다.
- 현재 메커니즘 카탈로그의 범위가 매우 제한적이며, 빌드 인사이트 규칙은 Fireball과 Arc에 집중되어 있습니다.
- API 카탈로그와 브라우저 PoB 분석은 모두 존재하지만, 단일한 최종 분석 파이프라인으로 완전히 통합되지는 않았습니다.
- 게임 데이터는 버전 의존적이므로, 카탈로그 항목을 추가하거나 갱신할 때 근거와 검토 상태를 함께 관리해야 합니다.

앞으로는 검토된 메커니즘 카탈로그를 확장하고, 빌드의 방어·자원 유지·아이템·패시브 트리 상호작용을 단계적으로 분석할 예정입니다.
