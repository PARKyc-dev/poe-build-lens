# 모노레포 애플리케이션 경계

## 선택 이유

PoE Lens의 사용자 화면, 분석 API, 향후 PoB 엔진 워커는 하나의 제품과 배포 흐름을 구성하므로 단일 저장소에서 관리한다. 구현은 `web`, `api`, `worker` 경계로 분리해 각 애플리케이션을 독립적으로 실행하고 검증할 수 있게 한다.

현재 `worker`는 PoB 엔진의 실행 방식과 인터페이스가 검증되지 않았으므로 예약 문서만 둔다. 운영용 Docker와 리버스 프록시는 워커 도입 시 함께 설계한다.

## 대안

Spring Boot가 React 정적 파일을 직접 제공하는 단일 프로젝트를 유지한다. 프론트와 API의 개발·검증 경계가 섞이므로 채택하지 않았다.

처음부터 워커와 Docker 구성을 추가한다. PoB 런타임과 성능이 아직 검증되지 않아 재작업 가능성이 크므로 보류했다.
