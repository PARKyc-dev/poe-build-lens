# PoB를 분석 기준 엔진으로 사용

## 선택 이유

`Spec`, `SkillSet`, `ItemSet`, 패시브 트리 데이터와 DPS·방어 계산은 PoB 형식과 게임 버전에 의존한다. 이를 Java에서 별도로 해석하고 계산하면 PoB 기능을 불완전하게 다시 구현하게 된다. 공식 PoB 릴리스를 고정하고 PoB가 import한 내부 상태와 계산 결과를 분석의 기준으로 사용한다.

PoB 원본은 수정하지 않는다. 공식 `HeadlessWrapper.lua`를 worker가 소유한 얇은 Lua adapter에서 호출하고 결과를 JSON으로 변환한다. 미병합 JSON-RPC PR은 참고 자료로만 사용하며 런타임에 포함하지 않는다.

초기 worker는 PoB 프로세스 하나에 요청을 직렬화한다. 추후 병렬화는 같은 `PobEngine` 계약 아래 독립 PoB 프로세스 풀을 추가하는 방식으로 수행한다.

## 대안

Java에서 PoB XML과 게임 계산 규칙을 직접 구현한다. 형식 변화, 구버전 호환, 트리 데이터와 계산 정확도를 지속해서 재구현해야 하므로 채택하지 않았다.

미병합 JSON-RPC 브랜치를 PoB 배포물로 사용한다. 필요한 기능은 많지만 공식 릴리스가 아니며 변경과 병합 상태를 통제할 수 없어 채택하지 않았다.

브라우저에서 PoB WASM을 실행한다. 서버 분석 일관성, 클라이언트 자원 사용과 운영 경계 검증이 먼저 필요하므로 현재 구조에는 채택하지 않았다.

## 재검토 조건

- 공식 PoB가 안정된 headless JSON API를 릴리스함
- 외부 adapter로 필요한 구성이나 계산 결과를 얻을 수 없음
- headless 스파이크에서 메모리 또는 처리 시간이 셀프호스팅 목표를 만족하지 못함
- A → B → A 처리에서 해결할 수 없는 상태 오염이 확인됨
